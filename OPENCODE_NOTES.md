# OpenCode из Microsoft Agent Framework: заметки

Срез на 2026-10-16. Версии: OpenCode CLI 1.19.1 (`bin\opencode.exe`), MAF 1.21.0,
Python 3.13, Windows 10. Модели — через OpenRouter, ключ берётся из `minimal_agent.py`.

Пометки в тексте:
- **[проверено]** — подтверждено запуском на этой машине;
- **[по исходникам]** — прочитано в коде OpenCode v1.19.1 или в его документации, запуском не проверялось;
- **[вывод]** — наше заключение из устройства кода.

## Что лежит в папке

| Файл | Что показывает |
|---|---|
| `opencode_agent.py` | базовый пример: главный агент MAF вызывает подагента `OpenCodeAgent`, тот запускает `opencode run`; одобрение пользователя перед запуском, таймаут |
| `opencode_cli_loop.py` | **вариант а**: OpenCode через CLI, а проверяет результат наш код (pytest); при ошибке — продолжение той же сессии OpenCode |
| `opencode_server.py` | **вариант б**: OpenCode в режиме сервера; каждый его запрос прав (запись файла, команда) решает наш код — здесь спрашивает пользователя |
| `opencode_ext\skills\python-style\SKILL.md` | скилл для OpenCode; лежит ВНЕ рабочих папок, чтобы OpenCode не мог его переписать |
| `bin\opencode.exe` | OpenCode CLI 1.19.1 из официального релиза github.com/anomalyco/opencode, в PATH не добавлен |
| `workspace*` | рабочие папки примеров, создаются при запуске |


сессии), `нет` (отказ).

## Вариант а или вариант б

| | а: CLI + наш цикл проверки | б: сервер + наши ответы на права |
|---|---|---|
| Как живёт OpenCode | отдельный процесс на каждую попытку | один сервер на задачу, общение по HTTP |
| Кто решает, что можно | только заранее заданные правила `allow`/`deny` | правила + наш код в момент действия (`ask`) |
| Право `ask` | не работает: OpenCode сам отвечает отказом | работает: запрос ждёт нашего ответа |
| Кто проверяет результат | наш код после каждой попытки | в примере никто; можно добавить так же, как в а |
| Следующая попытка | `opencode run --session <id>` | новый `prompt_async` в ту же сессию |
| Прерывание | убить процесс по таймауту | `POST /session/{id}/abort`, сервер живёт |
| Прогресс | после окончания попытки | по ходу работы (опрос или поток `/event`) |
| Сложность кода | ниже | выше: порт, пароль, ожидание старта, опрос |
| Когда брать | автоматические циклы фабрики: написать → проверить → исправить | действия, которые должен подтвердить человек или политика |

Варианты совмещаются: сервер из б плюс цикл проверки из а.

## Подводные камни

### Ключ и модели

1. **Ключ из окружения не срабатывает.** Десктопный OpenCode хранит свой ключ OpenRouter в
   `~/.local/share/opencode/auth.json`, и CLI берёт его в приоритете над `OPENROUTER_API_KEY`.
   У нас тот ключ отвечал 401 «User not found». Решение — ключ в конфиге запуска:
   `"provider": {"openrouter": {"options": {"apiKey": ...}}}`. **[проверено]**
2. **Каталог моделей OpenCode не совпадает с OpenRouter.** `xiaomi/mimo-v2.6-flash` в нём нет.
   Список — `bin\opencode.exe models openrouter`, формат имени — `openrouter/<модель>`. **[проверено]**

### Изоляция

3. **OpenCode подмешивает чужие скиллы и правила.** Без настроек он подхватил скиллы из
   `~/.claude/skills`; по исходникам ещё `~/.agents/skills` и `~/.claude/CLAUDE.md`.
   Отключается переменными `OPENCODE_DISABLE_CLAUDE_CODE=1` и `OPENCODE_DISABLE_EXTERNAL_SKILLS=1`
   (стоят в обоих вариантах). **[проверено для скиллов]** Глобальный `~/.config/opencode`
   подмешивается всегда (сейчас он пустой). **[по исходникам]**
4. **Агент может переписать свои правила.** Всё, что лежит в рабочей папке (`AGENTS.md`,
   `.opencode/agents`, `.opencode/skills`, `.opencode/plugins`), OpenCode читает как настройки —
   и может изменить, раз ему разрешена запись. Правила держим вне рабочей папки (конфиг,
   `skills.paths`), а на эти пути ставим `edit: deny` (сделано в варианте а). **[вывод]**
5. **Сессии видны в десктопном OpenCode.** CLI пишет их в ту же папку данных
   (`~/.local/share/opencode`). **[вывод из `opencode debug paths`]**

### Права

6. **У своего агента по умолчанию разрешено всё.** Тестовый агент сам запустил `python add.py`.
   Права задавать явно. **[проверено]**
7. **`ask` в `opencode run` — это отказ.** Запрос не зависает, а сразу отклоняется
   («The user rejected permission»); по исходникам цикл агента после этого останавливается.
   В CLI — только явные `allow`/`deny`; если нужен `ask`, это вариант б. **[проверено]**
8. **`--auto` одобряет всё, что не запрещено явно.** Скрытые синонимы — `--yolo` и
   `--dangerously-skip-permissions`. Не использовать. **[по исходникам]**
9. **Шаблоны путей в `edit` считаются от корня диска, если папка не git-репозиторий.**
   В запросе прав путь выглядит как `Users\...\hello.py`. Поэтому `"test_*.py": "deny"` тест
   НЕ защитил, а `"**/test_*.py": "deny"` защитил. Всегда писать `**/`. **[проверено]**
10. **Срабатывает последнее подходящее правило.** Общее `"*"` ставить первым, частные — после.
    **[по исходникам]**
11. **`bash` проверяется по каждой команде отдельно** (`a && b` — две проверки). Граница
    рабочей папки для оболочки не надёжна: это настоящая оболочка. Без нужды `bash` не давать
    (в варианте а он выключен — тесты гоняем мы). **[проверено: шаблоны; граница не проверялась]**
12. **С включённым `bash` ключ виден модели.** Конфиг с ключом лежит в переменной
    `OPENCODE_CONFIG_CONTENT`, а её наследуют команды оболочки; `set` или `echo` покажет ключ.
    Для боевого запуска ключ передавать иначе (отдельное хранилище учётных данных, прокси). **[вывод]**
13. **Встроенный субагент `task` тратит токены впустую.** OpenCode пытался прогнать тесты через
    своего субагента (у которого тоже нет оболочки). Отключено правом `"task": "deny"`. **[проверено]**
14. **`steps` — мягкий лимит.** На последнем шаге модель просят ответить текстом, но жёсткой
    остановки нет. Свой таймаут обязателен (есть во всех примерах). **[по исходникам]**

### Плагины и расширения

15. **`--pure` отключает и локальные плагины** из `.opencode/plugins`, не только npm-пакеты.
    С `--pure` плагин-сторож не загрузился и файл `.secret` записался. Нужен плагин — убрать
    `--pure`. **[проверено]** Свои инструменты из `.opencode/tools` флаг не отключает. **[по исходникам]**
16. **Хук `permission.ask` в плагинах не вызывается** — объявлен в типах, но в коде прав его
    вызова нет. Программные решения о правах — через сервер (вариант б). **[по исходникам]**
17. **Меняется схема конфига.** Опубликованная схема `opencode.ai/config.json` уже от OpenCode 2.0
    (`agents`, `permissions`, `plugins`), а 1.19 понимает старые ключи (`agent`, `permission`,
    `plugin`); ключ `permissions` в 1.x даёт ошибку. Версию CLI фиксировать: переход на 2.0
    сломает конфиг. **[по исходникам]**

### Сервер (вариант б)

18. **Пароль на сервер.** Без `OPENCODE_SERVER_PASSWORD` любой процесс на машине может управлять
    OpenCode через порт. В примере — случайный пароль на запуск. **[по исходникам]**
19. **Старт занимает несколько секунд** — ждём ответа `/global/health`. Порт берём свободный,
    остановка — в `finally`, чтобы сервер не остался висеть. **[проверено]**
20. **Конец работы определяется не только по статусу.** `/session/status` содержит только
    занятые сессии, а сразу после `prompt_async` сессия может ещё числиться свободной. Признак
    конца в примере — свободна И последнее сообщение — завершённый ответ модели. **[проверено]**
21. **Отказ с текстом — это обратная связь, а не остановка.** Модель получает объяснение и
    продолжает (не повторяет действие). **[проверено]**
22. **В сервере два API**: классический (`/session`, `/permission`, `/event`) из документации
    и новый `/api/...` (V2). Используем классический. **[проверено по `/doc`]**
23. **Опрос раз в секунду — для простоты.** Для интерфейса лучше поток событий `GET /event`
    (SSE): там есть `permission.asked`, части ответа по мере генерации, `session.idle`. **[по исходникам]**
24. **Ответы в консоли читаются по строкам.** Если подать на вход меньше строк, чем будет
    запросов, `input()` получит конец ввода и упадёт. В интерфейсе это были бы карточки. **[вывод]**
25. **Python SDK для OpenCode нет** (на PyPI только старая альфа 2025 года), поэтому HTTP
    написан руками на `urllib`. **[по исходникам]**

### Связка с MAF

26. **`as_tool()` всегда запускает подагента в режиме стрима** и ждёт у результата
    `get_final_response()`. Свой агент при `stream=True` должен возвращать `ResponseStream`;
    официальный пример MAF возвращает голый генератор и через `as_tool()` упадёт. **[проверено]**
27. **Запросы одобрения подагента не доходят до главного агента** через `as_tool()`. Поэтому в
    варианте б одобрение — колбэк `approve`, переданный в агента. Штатный путь MAF — workflow с
    `request_info`. **[проверено ранее, см. agents_async.py]**

### Windows

28. **Кодировка вывода.** Python в pipe пишет в cp1251, и кириллица в ошибках pytest доходила до
    модели кракозябрами. Для команды проверки ставим `PYTHONUTF8=1`. OpenCode сам наткнулся на то
    же при `python hello.py` и повторил с `PYTHONIOENCODING=utf-8`. **[проверено]**
29. **Длинные строки событий.** Событие записи файла содержит весь файл одной строкой; при
    построчном чтении нужен большой `limit` (`opencode_agent.py`), в варианте а — `communicate()`.
    **[вывод]**

## Где у OpenCode что настраивается (1.19, схема 1.x)

| Что | Файлы | Ключ конфига |
|---|---|---|
| Агенты (промпт, модель, права, `steps`) | `.opencode/agents/<имя>.md` (или `agent/`) | `agent` |
| Правила проекта | `AGENTS.md` (ищется вверх от папки), иначе `CLAUDE.md` | `instructions` — доп. файлы и URL |
| Скиллы | `.opencode/skills/<имя>/SKILL.md` (или `skill/`) | `skills.paths`, права — `permission.skill` |
| MCP-серверы | — | `mcp` (`type: local` с командой или `remote` с `url` и `headers`) |
| Плагины (JS/TS, Bun внутри бинарника) | `.opencode/plugins/*.js` (или `plugin/`) | `plugin` — пути и npm-пакеты |
| Свои инструменты | `.opencode/tools/*.ts` | — |
| Команды-шаблоны | `.opencode/commands/*.md` | `command` |
| Права | — | `permission`, у агента — своё `permission` |

Полный справочник по этой версии встроен в сам OpenCode — скилл `customize-opencode`:
`bin\opencode.exe debug skill`.

Проверенный плагин-сторож (блокирует запись и чтение файлов `.secret`; работает без `--pure`):

```js
// .opencode/plugins/guard.js
export const Guard = async () => ({
  "tool.execute.before": async (input, output) => {
    const path = String(output?.args?.filePath ?? "");
    if (path.endsWith(".secret")) throw new Error("запись .secret запрещена");
  },
});
```

## Сжатие контекста (compaction)

Когда история сессии перестаёт помещаться в окно модели, OpenCode сжимает её:
старую часть пересказывает отдельный скрытый агент `compaction`, свежие ходы оставляет
дословно. Источник — `packages/opencode/src/session/compaction.ts` и `overflow.ts`
из тега v1.19.1.

### Как это работает

1. После каждого шага модели OpenCode сравнивает число токенов шага с порогом. **[по исходникам]**
   - если у модели задан отдельный лимит входа: порог = лимит входа − `reserved`
     (по умолчанию `reserved` = min(20 000, максимум вывода модели));
   - иначе: порог = окно модели − максимум вывода.
2. Порог превышен → перед следующим запросом к модели история делится на две части:
   - **хвост** — последние ходы, которые влезают в бюджет `preserve_recent_tokens`
     (по умолчанию 25 % порога, но не меньше 2 000 и не больше 15 000 токенов), но не больше
     `tail_turns` ходов. Хвост остаётся дословно;
   - **голова** — всё остальное, её пересказывает агент `compaction`.
3. В историю добавляется сводка, после неё — хвост, и работа продолжается сама
   (автопродолжение). Предыдущая сводка учитывается при следующем сжатии.

Отдельно от сжатия есть **чистка (prune)**: стирает выводы старых инструментов (кроме `skill`),
оставляя последние ~40 000 токенов выводов и два последних хода. Срабатывает, только если
набралось больше 20 000 токенов на удаление. **В 1.19.1 выключена, пока не задано
`"prune": true`**. **[по исходникам; в разрешённом конфиге ключа нет]**

### Чем управлять

| Что | Как | По умолчанию |
|---|---|---|
| Выключить автосжатие | `"compaction": {"auto": false}` или `OPENCODE_DISABLE_AUTOCOMPACT=1` | включено |
| Включить чистку старых выводов | `"compaction": {"prune": true}` (выключить: `OPENCODE_DISABLE_PRUNE=1`) | выключено |
| Сколько ходов оставлять дословно | `"compaction": {"tail_turns": N}`; `0` — сжимать всё | ограничено только бюджетом |
| Бюджет дословного хвоста | `"compaction": {"preserve_recent_tokens": N}` | 25 % порога, 2 000…15 000 |
| Запас под ответ при расчёте порога | `"compaction": {"reserved": N}` | min(20 000, максимум вывода) |
| Окно модели (а с ним порог) | `"provider": {"openrouter": {"models": {"<модель>": {"limit": {"context": N, "output": M}}}}}` | из каталога моделей OpenCode |
| Промпт сжатия | `"agent": {"compaction": {"prompt": "..."}}` | встроенный |
| Модель для сжатия (можно дешевле основной) | `"agent": {"compaction": {"model": "openrouter/..."}}` | модель сессии |
| Размер вывода одного инструмента | `"tool_output": {"max_lines": N, "max_bytes": M}` — режет вывод до попадания в контекст | 2 000 строк, 50 КБ |
| Добавить свой контекст в сжатие или заменить промпт целиком | хук плагина `experimental.session.compacting` (`output.context`, `output.prompt`) | — |
| Не продолжать работу после автосжатия | хук `experimental.compaction.autocontinue` (`output.enabled = false`) | продолжает |
| Сжать вручную | сервер: `POST /session/{id}/summarize` с `{"providerID", "modelID"}`; в TUI — `/compact` | — |

Пример конфига: сжатие на дешёвой модели со своим промптом, дословно — 4 последних хода:

```json
{
  "compaction": {"auto": true, "prune": true, "tail_turns": 4},
  "agent": {
    "compaction": {
      "model": "openrouter/qwen/qwen3.7-flash",
      "prompt": "Сожми историю: цель задачи, что уже сделано, какие файлы изменены, что осталось."
    }
  },
  "tool_output": {"max_lines": 500, "max_bytes": 20000}
}
```

### Что проверено

| Проба | Результат |
|---|---|
| Окно модели занижено до 12 000 (порог 10 000), три задачи подряд в одной сессии | шаг вырос до 14 009 токенов → история сжата → следующий шаг 5 965; во втором запуске то же; 2 сжатия за сессию **[проверено]** |
| Свои промпт и модель агента `compaction` | обе сводки сделаны на `qwen3.7-flash` и начинаются с метки из нашего промпта **[проверено]** |
| Ручное сжатие через сервер | `POST /session/{id}/summarize` → `true` за 34,5 с; сводка тем же агентом и моделью **[проверено]** |
| Одиночный запрос с занижённым окном | сжатие не понадобилось: OpenCode читал большой файл кусками и не дошёл до порога **[проверено]** |

### Подводные камни сжатия

30. **Порог проверяется после шага.** Один шаг может заметно перескочить порог (14 009 при
    пороге 10 000), и только потом история сжимается. Если шаг перескочит реальное окно модели,
    запрос упадёт — поэтому `reserved` не стоит делать маленьким. **[проверено: перескок]**
31. **Модель из запроса `summarize` игнорируется,** если у агента `compaction` задана своя модель:
    в пробе просили `qwen3.8-27b`, сжимала `qwen3.7-flash`. **[проверено]**
32. **Синхронные методы сервера долгие.** `POST /session/{id}/message` и `/summarize` ждут ответа
    модели (у нас 30+ с) — HTTP-клиент с таймаутом 30 с падает. В `opencode_server.py` задача
    отправляется через `prompt_async`, там этой проблемы нет. **[проверено]**
33. **Сводка — пересказ, не копия.** Детали из сжатой части (точные числа, пути, решения)
    модель видит только в пересказе. Что обязано сохраниться — писать в промпт агента
    `compaction` или добавлять хуком `experimental.session.compacting`. **[вывод]**
34. **Длинный цикл исправлений упрётся в сжатие.** В варианте а все попытки идут в одной сессии
    (`--session`), история копится, и после порога ранние попытки модель увидит только в
    пересказе. Если важно, что именно уже пробовали, это стоит прямо перечислять в промпте
    следующей попытки. **[вывод]**
